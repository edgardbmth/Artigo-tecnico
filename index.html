1. O que é Normalização?

A normalização de bancos de dados é um processo formal de análise de esquemas de relação baseado em suas dependências funcionais e chaves primárias. Seu objetivo central é minimizar a redundância de dados e estruturar tabelas de forma lógica para evitar inconsistências em sistemas transacionais (OLTP).

2. Os Perigos: Anomalias de Inserção, Atualização e Exclusão

Quando um banco de dados não é normalizado e concentra tudo em uma única tabela grande, ocorrem graves problemas operacionais:

Anomalia de Inserção

Impossibilidade de registrar dados fundamentais (como um novo produto ou fornecedor) sem antes possuir uma transação associada.

Anomalia de Atualização

Modificar uma informação repetida em várias linhas e acabar alterando apenas algumas, gerando dados contraditórios na base.

Anomalia de Exclusão

Ao apagar o registro de uma venda ou pedido, perder permanentemente dados cadastrais importantes do cliente ou do produto devido ao acoplamento excessivo.

3. As Três Primeiras Formas Normais (1FN, 2FN e 3FN)

  • 1ª Forma Normal (1FN): Exige que os domínios de todos os atributos sejam atômicos, ou seja, sem grupos repetitivos ou campos multivalorados na mesma coluna.
  • 2ª Forma Normal (2FN): Deve estar na 1FN e todos os atributos não-chave devem depender inteiramente da chave primária inteira (eliminando dependências parciais em chaves compostas).
  • 3ª Forma Normal (3FN): Deve estar na 2FN e não possuir dependências transitivas (atributos não-chave dependendo de outros atributos que não sejam a chave primária).

4. Implementação Prática em SQL (PostgreSQL)

Abaixo temos um exemplo de script estruturado respeitando as regras de normalização relacional com integridade referencial rigorosa.

PostgreSQL | 01_normalizacao_tabelas.sql Repositório GitHub 
-- 1. Tabela de Clientes (Normalizada)
CREATE TABLE clientes (
    id_cliente SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL
);

-- 2. Tabela de Produtos
CREATE TABLE produtos (
    id_produto SERIAL PRIMARY KEY,
    nome_produto VARCHAR(100) NOT NULL,
    preco NUMERIC(10,2) NOT NULL
);

-- 3. Tabela de Pedidos (Relacionada por Chave Estrangeira)
CREATE TABLE pedidos (
    id_pedido SERIAL PRIMARY KEY,
    id_cliente INT REFERENCES clientes(id_cliente),
    data_pedido TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 4. Tabela Associativa de Itens do Pedido (Resolve N:M)
CREATE TABLE itens_pedido (
    id_pedido INT REFERENCES pedidos(id_pedido),
    id_produto INT REFERENCES produtos(id_produto),
    quantidade INT NOT NULL CHECK (quantidade > 0),
    PRIMARY KEY (id_pedido, id_produto)
);
